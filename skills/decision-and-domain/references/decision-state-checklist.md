# 决策与状态检查

## 决策字段

编号、状态、来源、背景、最终结论、禁止方案、适用范围、影响角色、页面、状态、数据、验收标准、确认人、确认日期、替代关系。

## 状态—证据—责任矩阵

每一行记录：对象或规则、类型、事实来源、写入或确认事件、责任方、派生关系、不可变条件、允许修正方式和下游消费者。

| 类型 | 回答的问题 | 防错要求 |
|---|---|---|
| `source-state` | 哪个业务对象真实持有状态，由什么可确认事件写入？ | 不由页面文案或展示需要反向创造 |
| `display-state` | 页面展示由哪些源状态、权限或时间条件派生？ | 只读派生，不成为新的源字段 |
| `external-evidence` | 哪个外部来源证明事件或结果发生？ | 记录来源、时间和责任方，不直接覆盖内部源状态 |
| `responsibility-owner` | 谁有权确认、写入、修正或解释该状态？ | 区分业务责任、系统记录和人工处理责任 |
| `immutable-rule` | 达到什么条件后结果不得重写或倒退？ | 写明生效条件、禁止动作、例外授权和验证方式 |

若一项同时涉及多个类型，拆成多行并保留关联，不把证据、展示和源状态压成一个字段。

## 状态压力测试

- 状态是否由系统能够确认的事件驱动？
- 是否把订单、物流、权益和异常混在一起？
- 是否把“进行中”“已完成”等展示文案落为源状态？
- 失败、取消、关闭是否有不同语义？
- 终态是否仍允许非法操作？
- 重复事件是否幂等？
- 乱序事件是否会倒退状态？
- 异常记录是否错误覆盖业务源状态？
