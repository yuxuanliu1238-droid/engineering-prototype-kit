# 业务文档与采用基线

需求正文采用“文档信息、系统边界、角色权限、功能架构、页面详细需求、核心业务逻辑、业务流程、数据记录、权限安全、非功能要求”。页面按目标、结构、动作、字段、必要状态与异常展开，复杂规则集中说明并引用；未涉及的表格可省略。

接口正文采用八章：对接流程与业务边界、接口总览、环境与通信约定、接口明细、错误码建议、超时重试与日志、联调验收、联调前待确认。每个接口说明调用方式与时机、请求字段、响应数据、必要格式示例、处理规则。先说明现场作业，区分请求拒绝、业务失败、处理中与超时；取消、重复、乱序、迟到结果按实际范围说明，不预设通用业务取舍。

Kit 中使用 `pnpm project:material -- --project <业务目录> --activation business-requirements` 或 `interface-specification` 预览；用户已授权准备材料时增加 `--apply`。首次同时准备空的文档基线；目标已存在时停止，不重建已有正文。`--restore latest` 恢复对应材料事务，后续修改会阻断恢复。

基线位置由 `config.paths.documentBaseline` 指定。JSON 使用 `schemaVersion: 1` 和 `documents` 数组，每条包含：

| 字段 | 含义 |
| --- | --- |
| id / type | 稳定引用 ID；type 为 requirement 或 interface |
| locator / revisionLabel | 在线或本地位置、实际采用修订，不凭版本名称猜先后 |
| readAt 或 reviewedAt | 读取或复核的日期时间 |
| sections | 本次采用章节，非空数组 |
| confirmationEvidence | 明确采用的确认引用，非空数组；来源文字不等于业务批准 |
| snapshotPath / sha256 | 可选本地快照及摘要，成对提供，快照不成为第二正文 |

基线条目只在明确采用修订后登记。在线文档变化需重新读取并确认采用范围，不以时间较新自动推翻决策。CR 的 `documents[]` 可引用条目 ID 或文档 locator；`task:context` 仅展开本条需求引用项。使用 `pnpm documents:validate` 检查离线结构、引用和摘要；它不会访问在线文档或证明其仍为最新版。

需求、接口、Demo 三方对照使用“业务事项—需求依据及章节—接口约定—Demo 行为—差异—确认方”。问题分为业务确认、产品统一、研发约定。文档修订变化后，旧对照只能标记为“未按新基线验证”。已确认事项回写正文，待确认只保留尚未决定内容。

不从隐藏 mock 字段反推正式接口；未确认路径、鉴权和错误码写待设计。测试样例须提供输入、有效配置及预期输出，格式示例不替代验收依据。
