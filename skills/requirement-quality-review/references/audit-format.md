# 审查输出与对抗样本

## 字段

问题编号、等级、确认状态、问题性质、主问题类型、辅助标签、涉及文件、章节、原文片段、基线依据、基线有效性说明、问题说明、影响、建议修改、回写目标。

## 对抗样本

- 合理展示态不应误报为源状态。
- 展示态被写入源状态必须发现。
- 已移除项出现在历史说明中不应误报。
- 已移除项进入正式接口建议必须发现。
- 页面没写但没有写错，应判信息缺失。
- 旧决策不能压制更晚的有效决策。
- mock 隐藏字段不能自动升级为页面需求。
- 契约有动作但原型不可操作，必须判同步未完成。
- `aiPolicy: unassessed` 但执行状态为 `ready`，必须阻断。
- 已授权但验收或风险未评估，不能判定为 `execution-ready`。
- `waiting-human` 只写“需讨论”而无唯一问题，必须判结构缺失。
- `completed` 只有普通链接而无类型化产物，必须阻断。
- 产物存在但 `supports` 不覆盖任何验收 ID，应报证据缺失。

## 按风险选用的行为反例

只选当前范围内少量关键规则，记录“规则依据—错误实现—捕获测试及结果”，不规定所有项目必填或统一得分。错误实现仅在隔离样本中验证。

- 错误实现跳过授权或状态约束，测试仍通过：报告漏检，不能用通过数量证明规则已覆盖。
- 验收失败后放宽已确认规则或验收：报告未经确认的口径变更，追溯上游依据，不局部改写预期来掩盖失败。
- 业务意图经产品确认改变：重新验证直接受影响的接口、页面和测试，不用旧结果支撑新结论。
- 证据卡只有 AI 自述，或未记录自主决策：前者不能证明已验证，后者标记待核对，不能自动判定没有偏离。

## 证据新鲜度与退役残留对抗矩阵

| 样本 | 应判定为问题 | 判断依据 |
|---|---|---|
| `stale-fingerprint` | 是 | 报告指纹与当前覆盖文件不一致，旧的通过结果已经过期 |
| `incomplete-covered-files` | 是 | 指纹匹配但遗漏了与验收项直接相关的变化文件，覆盖范围不足 |
| `failed-or-not-run-report` | 是 | 指纹新鲜不能把失败或未执行的报告变成通过证据 |
| `retired-id-active-residue` | 是 | 已退役 Page、Action 或 State ID 仍出现在当前契约、路由、原型、测试、fixture 或生成内容 |
| `retired-id-history-trace` | 否 | 旧 ID 只存在于明确标记的归档、不可变快照或历史报告，用于追溯 |
| `removed-copy-current-output` | 是 | 已删除内容仍进入当前正文、接口建议、待确认池或生成交付内容 |
| `removed-copy-archive-only` | 否 | 已删除内容仅保留在有明确历史语义的材料中 |

先核对退役或删除依据及生效点，再搜索当前事实源和生成链路，最后单独检查历史目录。不能仅凭字符串命中就把历史追溯误判为当前残留。
