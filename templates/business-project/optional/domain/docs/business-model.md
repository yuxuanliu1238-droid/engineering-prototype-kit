# 业务模型

> 启用原因：对象生命周期 / 多角色责任 / 异常恢复 / 核心状态变化。
>
> 未触发上述复杂度时，不创建本文件。

## 1. 领域对象

| 对象 | 职责 | 创建方 | 处理方 | 查询方 | 终止方式 | 关键不变量 | 确认状态 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  | 待确认 |

## 2. 状态机

| 状态编码 | 所属对象 | 业务含义 | 进入条件 | 触发事件 | 操作角色 | 下一状态 | 可逆 | 禁止操作 | 页面展示 |
|---|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |  |  |

展示态只能由源状态组合计算，不能反向驱动业务状态。

## 3. 异常与恢复

| 异常编号 | 触发条件 | 所属对象 | 是否改变源状态 | 负责人 | 处理方式 | 恢复/关闭条件 | SLA | 确认状态 |
|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  | 待确认 |

## 4. 动作准入与页面投影

| 动作 | 所属对象 | 允许状态 | 禁止状态 | 成功后状态 | 失败后状态 | 出现页面 | 是否仅用于评审 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  | 否 |

页面状态、列表标签和异常待办均从同一个源状态计算。异常可以生成待办，但不得在没有明确业务含义时复制一套并行状态。仅用于 Demo 评审的动作必须单独标记，不进入正式业务需求。

## 5. 压力测试

- 重复和乱序事件如何处理；
- 失败、取消和关闭是否混用；
- 是否存在系统无法确认的源状态；
- 角色责任和状态操作是否一致；
- 外部系统失败后如何恢复或人工兜底。
- 同一源状态在列表、详情和异常页面是否一致；
- 每个动作是否只在允许状态出现，成功和失败后是否有明确状态；
- 异常关闭是否真正消除根因，还是只关闭了待办。
