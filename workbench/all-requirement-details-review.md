# 全量需求只读详情扩展

## 本批实现

1. `src/requirement-detail-model.js`：只投影台账中的阶段、状态、范围、等待原因、确认日期、说明、页面、文档及证据，不推断时间或自动提升状态。
2. `src/requirement-details.json`：28 条需求的必要字段快照，带来源、读取时间及 SHA-256；关联文件仅检查存在性，不读取全文。
3. `src/source-requirements.js`：三个入口与详情统一读取这份快照。
4. `src/SourceWorkspace.jsx`、`src/ReadOnlyRequirement.jsx`：去除 CR-027 专用分支，全量使用已验收的时间轴与详情结构。按每条记录展示已完成、等待或待启动等状态；切换需求重置局部选择。
5. `src/RequirementPages.jsx`：空页面提示、正确的移动端／后台／小哥／服务页标签，保留集中摘要与全部展开收起。
6. `src/requirement-presentation.js`、`src/RequirementEvidenceGraph.jsx`：纳入台账明确关联的文档节点；每组最多 12 个关联节点，可逐组查看，避免大量证据重叠。连线仅表示该需求引用，不表达因果或验收结果。
7. `src/styles.css`：证据分组控制和长时间轴滚动。
8. `scripts/test-all-requirement-details.mjs`：全量模型、差异状态、缺失字段、关系图分页完整性测试。

## 验证结果

- 工作台构建通过。
- 11 项相关逻辑测试通过。
- 28 条详情逐条 React 服务端渲染通过，包含已完成和无关联页面场景。
- 全量详情投影逐字段与源台账一致，源文件摘要一致；关系图所有分页均可覆盖全部节点，无重复或越界。
- 本地预览 HTTP 200。
- 实际缺项：6 条未登记关联页面，8 条未登记正式文档；已明确提示。已检查的文件引用没有发现缺失文件，但未核验文件内容。

## 边界与待验收

沿用页面构建技能的少文字、折叠及分层呈现规则。未进行浏览器交互或视觉测试：本轮未明确请求浏览器测试，服务端渲染不能替代点击与视觉验收。用户需复核时间轴选择、全展开／收起、节点选择与分页。

资料为读取时快照，不实时同步；页面摘要使用上一批页面契约快照。历史检查没有重跑，历史确认没有升级为本次授权。缺失时间没有补造；未读取生产数据、修改业务项目、写回台账、提交或发布。

旧单条及摘要 JSON 保留为历史测试样本；运行入口使用全量快照，不存在两套活跃需求状态。下一批未获授权。
