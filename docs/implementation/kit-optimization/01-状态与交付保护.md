# 第一批：状态与交付保护

优先级：P0／P1。实现与自动检查已完成；本轮安排的状态提示产品验收已确认，范围见 [产品验收记录](06-产品验收记录.md)。

## 对你的实际好处

状态卡不再把“材料看起来齐了”直接理解为“可以开工”。锁定、暂停、取消、等待人工有明确结果；旧完成记录保留，但证据不足会标为“未按新规则验证”。即使引用已登记，状态卡也提示执行前实时核验，不替代检查器。

## 前后对比

| 以前的风险 | 现在的行为 | 你得到的好处 |
| --- | --- | --- |
| 锁定任务仍可能显示可以实施 | 明确显示锁定 | 不会因一个绿色状态误开工 |
| 完成引用只是字符串 | 新门禁要求确认来源、日期、验收对应关系；检查报告还需有效且新鲜 | 能追问到完成依据 |
| 跳过活动没有原因 | 跳过须有理由与确认引用，产品最终评审禁止跳过 | 遗漏变成可见决定 |
| 复盘漏掉暂存区 | 同时收集暂存、未暂存和新增文件，保留重命名前后路径 | 提交前的真实改动不会漏看 |
| 待确认问题不出现在评审包 | 使用当前 openQuestions 字段 | 评审时看到尚未解决的问题 |
| 多处版本号漂移 | 包版本 0.4.0 为生成来源 | 新建与升级对版本有一致理解 |
| 打包靠排除少数目录 | 允许清单、敏感文件禁入、生成后复查归档 | 降低误带配置、私钥、缓存的风险 |
| 写入可能经过符号链接 | 公共路径保护拒绝项目内部符号链接 | 避免把输出写到项目之外 |

## 自动验证

已通过：锁定／证据不足／旧完成状态卡反例、非法成员、跳过门禁、问题展示；路径越界、敏感条目禁入；Schema v3、暂存重命名、删除、中文空格与制表符文件名；合法新建、生成、校验、升级路径及 0.4.0 版本检查。

两类包均已在本地验证：Kit 归档条目与校验和通过；隔离业务项目实际检查、构建及评审包生成通过。

## 边界与验收

本地文件确认记录不等于独立身份认证；外部链接由明确人工核验记录支撑，不声称已联网核实。归档政策检查文件路径和扩展名，不能识别任何任意命名源码里硬编码的秘密。

建议产品验收看三件事：锁定不会催促开工；旧完成记录不会被改写却能看见证据缺口；评审包包含待确认问题。
