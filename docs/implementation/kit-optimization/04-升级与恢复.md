# 第四批：升级与恢复

优先级：P1／P2。保护机制与隔离回归已完成。

## 对你的实际好处

升级前能看清影响；预览后文件又变了，工具会要求重新预览。升级失败有备份和阶段记录；恢复发现你后来改过文件时会停下来，不直接覆盖。

## 当前实现

- 管理运行时文件由模板 manifest 派生，新建、升级、模式切换、迁移及交接启用共用入口。
- 新建先在临时目录生成并核验摘要，再以事务写入空目标；原有非空目录不会覆盖。
- 升级、模式切换、迁移和交接启用采用暂存、备份摘要核验、写前再比对、写入、最后更新清单的流程。
- 同一项目使用互斥操作锁；检测未完成事务，不能直接叠加下一次修改。
- 恢复先整体检查备份与当前摘要，再写回；后续用户修改与备份损坏明确报冲突。
- 旧版缺少写后摘要的备份不盲目恢复，提示人工核对。
- 保留旧迁移 rollback 参数；统一解析时发现的兼容回归已修复。
- 自定义已登记的台账、摘要、交接来源和任务视图路径在启用、生成和校验中一致。

## 自动验证

已通过：暂存完成、备份核验完成、写入后、验证后的合成阶段故障；逐文件写入故障；原文件恢复、新建文件移除；预览后变化、备份损坏、升级后用户修改、同进程并发锁阻断。

现有项目工具测试覆盖新建两种模式、模式门禁、旧版迁移／恢复及升级保护。独立安装实例最后又执行了升级预览、应用和业务检查。

## 边界与验收

故障注入是进程内合成测试，未做真实断电或强杀每个系统调用的穷举测试。操作锁和摘要保护面向日常协作，不是抵御恶意并发替换文件的操作系统级事务。

没有操作 cx回收、达能；未自动覆盖或迁移真实业务数据。自定义路径测试模拟的是已登记配置，不代表允许绕过管理文件校验。

建议产品验收：在隔离样例中观察预览、冲突和恢复结果，确认不会悄悄吞掉已有修改。
