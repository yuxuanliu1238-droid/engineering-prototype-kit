# 第三批：可复核检查

优先级：P1／P2。执行器与业务交付入口已接通。

## 对你的实际好处

你可以区分“AI 说查过了”和“工具确实运行并通过了”。检查结果会说明已验证、未验证、阻断项、需谁确认和下一动作；通过检查不会自动完成需求。

## 前后对比

| 原风险 | 当前行为 |
| --- | --- |
| 调用者填写一个 passed 就像验证成功 | 执行器启动实际进程，记录退出码、耗时和超时情况 |
| 失败报告只因时间新就被认可 | 执行结果、新鲜度和覆盖完整性分别判断 |
| 新增或删除文件未失效 | 指纹覆盖文件集合、内容、配置、锁文件、运行时及检查器版本 |
| 范围不明仍缩小检查 | check:scope 当前统一保守回退全量适用检查 |
| 旧缓存被不同任务复用 | 任务、输入和命令完整匹配才可复用；正式交付禁用缓存 |
| 机器通过等于业务认可 | 固定注明产品业务结论和最终人工评审未由自动检查验证 |

报告包含 schemaVersion、target、executedAt、result、runs、coverage、coveredFiles、sourceFingerprint、checkerVersion 和 nodeVersion。新交付须有实际检查；旧报告仍可读取，但不能冒充新规则验证。

统一校验结果新增 valid/issues 结构，每项包含 code、field、中文 reason、nextAction；保留原中文输出。旧校验器不能准确提供字段位置时回退到校验入口，不虚构精确位置。

## 自动验证

通过：真实成功、真实失败、空覆盖拒绝、缓存复用；修改源码／配置、添加锁文件／检查器、新增和删除文件使旧结果失效；不完整覆盖不能通过。隔离业务项目最终执行了检查与构建，并成功生成评审包。

## 边界与验收

当前没有经过验证的完整影响图，因此未启用精确缩小范围。缓存减少重复运行，但不能保证所有检查都很快。报告是本地工程证据，不是防篡改第三方审计系统；检查通过也不能证明业务规则正确。

建议产品验收：每次查看结果时能回答“查了什么、没查什么、卡在哪里、谁确认、接下来做什么”。
