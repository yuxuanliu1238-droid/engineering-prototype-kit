# 需求审查基线

## 审查边界

审查默认只报告问题，不直接修改决策、状态机、契约、原型或页面说明。

## 分场景事实源

先核对当前明确采用的需求、接口文档修订及章节，与有效决策共同确定本轮业务约束。在线正文可作为明确采用的事实源，不归为普通历史材料；本地草稿、镜像、旧快照只按标注用途使用。双方冲突时报告待统一，不依据名称、编号或更新时间自动覆盖任何一方。

按需文档基线由 `config.paths.documentBaseline` 指定，任务只展开直接引用项。离线结构、引用和摘要通过不代表在线最新版已核对。采用修订改变后，旧对照结论标记“未按新基线验证”。

### 业务规则和范围

1. 当前明确采用的需求、接口文档修订及有效决策。
2. 当前状态机。
3. 当前页面契约。
4. 当前原型。
5. 页面说明。
6. 原始资料和历史材料。

### 页面可见字段和实际操作

1. 当前明确采用的需求、接口文档修订及有效决策。
2. 当前页面契约。
3. 当前原型。
4. 页面说明。
5. 原始资料和历史材料。

页面契约和原型冲突时，视为同步未完成。

需求—接口—Demo 审查记录业务事项、需求依据、接口约定、Demo 行为、差异和确认方。问题按业务确认、产品统一、研发约定归属；未涉及的正式材料不因缺失而报错。

## 问题性质

- 事实冲突：明确写了与有效基线相反的内容。
- 信息缺失：缺少必要信息，但没有写错。
- 结构缺失：缺少约定章节、字段或编号。
- 表达不清：可能产生不同理解，但未形成明确冲突。

## 等级

- P0：可能导致核心业务、状态、责任边界、安全或范围错误。
- P1：可能导致页面、测试或实现理解不一致。
- P2：结构、截图、格式、完整性和表达精度问题。

确认状态与等级分开：无需确认、需产品确认、需业务确认、需研发确认。
