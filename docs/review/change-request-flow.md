# V0.3 增量需求流程

## 适用范围

正式 CR 只在 `continuous-iteration` 模式中创建。`rapid-validation` 只维护验证目标、范围、核心流程、假设、待确认问题、Demo 和评审结论。

## 启动规则

- “记录需求”只登记，不实施；
- AI 先提出风险等级、触发因素和活动清单，产品经理确认；
- 只有产品经理明确授权本条 CR，且就绪检查满足时才能实施；
- 影响分析前不得根据标题预填 Page、Action 或 State ID；
- 实施完成只进入待评审，产品经理最终确认后才进入已完成。

## 五阶段流程

1. `recorded`：保留原始请求、来源和登记时间；AI 策略可保持未评估。
2. `analysis-confirmation`：确认范围、风险、规则、验收、依赖和实施授权。
3. `implementation`：执行风险驱动活动并登记类型化证据。
4. `awaiting-review`：实施与检查完成，等待产品经理评审。
5. `completed`：产品经理确认符合范围和验收标准。

活动状态只使用：`未开始、进行中、等待用户、已完成、已跳过、被阻塞`。

## 风险活动

轻量需求不强制创建页面契约；标准需求覆盖契约、原型与一致性检查；高风险需求只对实际触发的决策、生命周期、异常、权限、安全或外部系统增加专项活动。

## 默认状态卡

产品经理默认看到五项：当前阶段、当前结论、原因、责任人和下一动作。`aiPolicy`、七项就绪检查和内部枚举按需展开。

## 关闭条件

- 所有活动已完成，或有明确理由跳过；
- 相关检查通过并有类型化产物；
- 产品经理评审结论为通过或有条件通过；
- `executionState` 与主阶段同时为完成；
- 未解决风险和问题仍被保留，没有因完成而自动消失。
