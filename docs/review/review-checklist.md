# 需求质量审查总控清单

## 固定顺序

1. 任务控制和授权合规审查。
2. 页面文档结构合规审查。
3. 需求口径一致性审查。
4. 决策落地一致性审查。
5. 产物与验收覆盖审查。
6. 合并去重。
7. 真实样本和对抗样本验证。
8. 人工确认 P0、P1 和待确认项。
9. 确认后再修复。
10. 修复后重新检查。

## 任务控制审查

- 阶段和执行状态未混用。
- AI 策略有明确授权证据。
- `ready/in-progress` 的就绪检查完整且可追溯。
- `waiting-human` 有唯一问题、确认方、影响和恢复条件。
- `completed` 有类型化产物，且产物覆盖验收事实。

## 需求、接口与 Demo 对照

- 标注正文事实源、采用修订和章节；在线已确认文档与本地决策冲突时报告待统一
- 需求按页面目标、结构、动作、字段与必要异常展开，复杂逻辑集中说明
- 接口按业务流程、总览、公共约定、明细、错误、重试日志、验收、待确认组织
- 对照同一事项的需求依据、接口约定、Demo 实际行为，明确差异与确认方
- 问题分别归属业务确认、产品统一、研发约定；已确认事项不重复列为待确认
- 基线改变后，旧对照显示“未按新基线验证”；离线校验不能证明在线最新
- 快速模式或未开启交接时，不因缺少正式 CR、契约或研发任务材料报错
- 验收失败有根因层级和源证据；上游业务意图变更经产品确认，并重验直接受影响产物
- 按风险选少量错误实现检验关键规则；证据卡的决策、偏离说明有来源，记录空白不等于没有偏离

## 去重规则

同一基线规则、同一业务根因、同一修正动作，只报告一次。

## 每条问题字段

- 问题编号。
- P0/P1/P2。
- 确认状态。
- 问题性质。
- 主问题类型。
- 辅助标签。
- 文件和章节。
- 最小证据。
- 当前有效基线及有效性说明。
- 问题、影响、建议。
- 回写目标。

## 退出条件

- P0 为 0。
- P1 已解决或明确阻断后续交付。
- P2 已记录。
- 修复有证据且重新检查通过。
